**Verdict: not ready.** D-017 clearly records the owner’s change of backbone, and the rewrite covers memory, persona consistency, instruction following, and responsiveness. The principal TaoMate-H3 code claims are also mostly accurate. The blocking problems are in the proposed timing loop and the claim that the LTX comparison isolates control granularity.

1. **Blocking — §6.4 understates latency by one request under the adopted gate.** D-015 says that when request \(n\) starts presentation, the gate starts generating \(n+L+1\). With \(L=1\), a newly arriving instruction misses that launch; even with zero processing time, its ideal TVC is \(U(0,5)+10\) seconds, with a **12.5-second median**, before playback and visual delay. Section 6.4 instead uses \(U(0,5)+5\), yielding its roughly 8-second median. Under D-015, even the idealized fraction meeting §8’s 12-second deadline is at most 40%, versus the 80% target. **Resolve:** specify the teacher, generation, gate, and presentation events on one timeline; either revise the targets or explicitly replace D-015 with a demonstrated \(L=0\) design.

2. **Blocking — a displayed failure cannot correct request \(k+2\) with the stated \(L=1\) schedule.** Request \(k+2\) begins generation when \(k\) starts presentation, and its audio teacher must already have its prompt. A VLM cannot inspect the displayed portion of \(k\) before then. This conflicts with §5.4’s correction into \(s_{k+2}\) and RQ2’s two-request remedy. Checking the *whole* request \(k\) makes the deadline later still. **Resolve:** timestamp when each chunk becomes visible, when VLM feedback arrives, and when the next teacher prompt is locked; test the earliest request that can actually accept a correction.

3. **Blocking — RQ3 equates LTX’s roughly one-second generation chunks with one-second instruction control.** The supplied TaoMate-LTX code study says its interactive demo selects a prompt **per roughly five-second window**, which contains five chunks. No cited code establishes a new prompt and matching speech every one-second chunk. Thus §6.4’s 2–3-second LTX TVC is unsupported. Further, H3 and LTX differ in backbone, memory, audio path, size, and runtime, so an H3–LTX TVC difference cannot be attributed to granularity. **Resolve:** first demonstrate and time one-second prompt changes on LTX; test one- versus five-second control within that same backbone, and label the H3–LTX result a system comparison.

4. **Major — the audio teacher’s resource and scheduling cost is outside the feasibility model.** The inspected H3 command completes audio preparation for all prompts before launching the worker (`cli.py:219–229`); the proposed resident, concurrent teacher is new engineering. The published 14.810-second DiT result for 10 seconds of video and 17.287-second first-playable benchmark both **exclude internal audio preparation**; the shipped output path also publishes only at the end. [H3 README](https://github.com/TaoLiveAIGC/TaoMate-H3). Because the student consumes teacher milestones, §6.4’s \(\max(G,G_a)\) requires a proved overlapping schedule and sufficient GPU capacity for both models. Average DiT time below five seconds alone would not establish full-pipeline throughput. **Resolve:** make M0 measure simultaneous teacher/student memory, contention, decode and mux time, and per-request deadlines over the proposed 30-minute run.

5. **Major — “re-anchoring” has no defined effect on this T2AV backbone.** [CANVAS](https://arxiv.org/html/2604.13452) conditions generation on **canonical images**; [A²RD](https://arxiv.org/html/2605.06924) can use boundary frames and, for interpolation, a planned end frame. The available H3 path accepts neither. BlockScript already repeats the canonical appearance and scene text verbatim on every request, so “restate the anchor when drift is detected” does not specify a changed input. Its first-chunk KV sink also remains in place. **Resolve:** define a distinct, executable intervention—such as a tested prompt change or a reset with a measured seam—and compare it with ordinary prompt repetition. Call it textual correction unless image conditioning is actually available.

6. **Major — interruption can leave the generator continuing from video the user never saw.** Section 5.4 stops client playback and discards *unsent scripts*, but an in-progress H3 request can still commit KV and advance the teacher’s audio tail. A later request may then depend on discarded action and speech, while the ledger records only presented content. Pre-rendered reaction clips add a second visual and audio discontinuity. **Resolve:** specify cancellation and rollback to the last presented chunk, or a reset path with measured delay and seams. Keep §8’s sub-second **visual acknowledgement** distinct from a meaningful generated reply.

7. **Major — several experimental claims exceed what the controls establish.** RQ2 selects “first failures” after treatment; randomize *repeat versus refinement* at the same independently defined failure point. RQ3’s “not significantly worse” adherence is not a non-inferiority test; set a margin and power it. For RQ4, add H3-only ledger and re-anchoring ablations; LTX is a descriptive comparison, not a controlled memory contrast. The 60-trial ICC pilot and stated 12–15 percentage-point detectable difference lack baseline rate, within-task correlation, and multiple-comparison assumptions; ten long sessions also need a session-level precision calculation. B0 mainly tests whether people prefer interaction to a fixed loop. **Resolve:** preregister estimands and simulation-based sample sizes, and keep the blinded human verdict independent of the online monitor as already planned.

8. **Major — voice, spoken content, and reasoning need explicit acceptance tests.** H3 has text-prompt voice control but no released voice reference; its base-model teacher supplies the final audio, so the LLM cannot stream independent TTS or guarantee that the spoken words match its transcript. E3’s “TTS voice” label is therefore incorrect for the avatar. Speaker embeddings alone do not test a stable voice across restarts; “讲讲 CUDA” being spoken does not test whether the explanation is correct or safe. **Resolve:** measure generated-speech transcript fidelity, cross-session speaker identity, factual reasoning, and spoken-content safety. Verify leakage in generated audio itself: ASR errors can hide it. The proposed 300-user exact <1% bound requires **zero** observed user-level leaks and covers the stated speech channel, while screen and image channels receive only descriptive testing.

9. **Minor — tighten source labels and the Google-suite description.** The code supports five-second H3 prompts, four chunks, sink plus two recent KV commits, teacher overwrite, lack of an injection API, and an FA3-only shipped path. The SM90 hardware requirement is documented by the [H3 README](https://github.com/TaoLiveAIGC/TaoMate-H3), while the local CC 8.9 observation is a hardware measurement, not a code finding. The 0.68× rate is **DiT-only**. H3 also carries offsets, first-chunk normalization statistics, and an audio-teacher tail, so “state only consists of KV” is too absolute. CANVAS primarily produces a storyboard; the cited minutes-per-segment overhead belongs specifically to A²RD. [Co-Director’s](https://arxiv.org/html/2604.24842) full-pipeline bandit pulls and [VQQA’s](https://arxiv.org/html/2603.12310) selection among regenerated candidates support the inspiration, but they do not validate the proposed cross-session bandit or forward-only correction. **Resolve:** separate verified source mechanisms from the new, untested online mechanisms throughout §2–§3.

The rewrite meets the **documentary** part of the owner’s directive: TaoMate-H3 is the named base, LingBot-World is explicitly repositioned, and science is separated from engineering. It needs a consistent causal schedule and experiments that test the claimed interventions before it is ready for approval.
