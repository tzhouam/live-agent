Based on the inlined material, the camera-only boundary is mostly stated correctly. The main CP3 problem is that several comparisons and latency claims assume extensions whose behavior has not yet been established.

1. **Blocking — A1 is not an executable prompt-only baseline as written.** LingBot registers only `camera` for stepwise `session.interaction` (`registry.py:25–27`); an unsupported prompt reaches `get_handler()` and raises (`coordinator.py:59–65`). A1’s “free-form prompts” therefore require C1, a different backend, or session restarts. Specify one implementation and use the same prompt capability in A1 and A2.

2. **Blocking — The proposed backlog gate has no demonstrated control mechanism.** `session.ping` refreshes the stall clock; the API gives it no progress or flow-control semantics. `serving_video_output_stream.py:148–155` sends each available chunk without an explicit playback timer, which supports the narrow “no server pacing” claim, although `send_bytes` can still experience transport backpressure. C4 needs an explicit server gate or a demonstrated client backpressure mechanism. Measure generated, received, decoded, and presented queue depths.

3. **Major — C1 is more than handler registration, and its proposed call is not verified by the quoted code.** The stepwise excerpts encode once at `pipeline.py:1893–1935` and call `_ar_text_caches(..., invalidate=False)` at `2053–2056`. The audit reports tick-path invalidation, but no excerpt establishes that the same `invalidate=True` call works safely for a changed stepwise prompt. C1 must specify how new embeddings enter session state, when K/V is rebuilt across ranks, and what happens during prompt transitions; test both a successful visual change and unchanged camera interaction.

4. **Major — Some interface claims have weaker evidence than their “A” label suggests.** The supplied API document describes camera `target`/`velocity`, `transition_chunks`, event acknowledgements, `session.stop`, and `image_reference`; the supplied code excerpts directly establish only parts of that path. The `9 + 12k` constraint is supported by the backbone audit’s cited validation lines, while `pipeline.py:2186–2197` alone establishes emitted chunk sizes. Keep “documented,” “code-read,” and “executed” distinct, and include a minimal WS contract test in M0. Event IDs acknowledge application to a chunk, never visible compliance.

5. **Major — A camera command does not implement “walk slower” or “walk toward the lake.”** The audited camera path changes viewpoint; it has no character-motion control. Third-person walking is prompt-conditioned behavior, and mid-session prompts need C1 and calibration. The first demo should promise camera turns and a visible host, with walking and scene events explicitly conditional on measured success. “No training needed” is sound for that narrower demo, not for reliable character behavior.

6. **Major — The architecture comparison confounds its treatments.** A0 has a memory layer, A1 has chat history, and A2 has typed memory; RQ4 cannot isolate the world model under those assignments. A1 and A2 must also share shot rendering and executable generator controls for RQ1. Add matched-memory and matched-renderer comparisons. Evaluate SGLang’s reported prompt-switching server, the latent-only tick path, clip scheduling, compositing, and a different world backbone as explicit feasibility alternatives. A3(b), adopting an existing duplex model, does not inherently require training, so the table’s blanket “Yes” is incorrect.

7. **Major — The IR does not yet define a compilable camera contract.** `yaw_deg: -60` could mean an absolute target or a relative turn; the WS camera payload requires translation plus quaternion. Define coordinate frame, units, reference pose, velocity duration and stop, timing origin, and how supersession works after an event is queued. The sequence figure’s “cancel pending events newer than current chunk” conflicts with §5.5’s rule to cancel items from older plan versions. A golden IR-to-WS example for correction and stop would settle this.

8. **Major — The monitor’s online decision is underspecified.** Sparse flow plus an essential matrix cannot recover translation scale and can fail under pure rotation, weak texture, or independently moving generated content. A VLM’s cited throughput is not an end-to-end verdict latency or accuracy guarantee at 480p. Define sampling, abstention, human-grounded error rates, verdict deadlines, and repair eligibility. Because monitoring is called asynchronous, report separately whether a verdict arrives early enough to repair before the original deadline.

9. **Major — The generated-event quarantine does not fully prevent false user facts.** “Only user-speaker turns feed extraction” still promotes “You told me my sister lives in Paris” unless the extractor distinguishes a user’s own assertion from a quotation or claim about the persona. A user repeating a persona invention and a persona paraphrasing a genuine user fact require lineage through `derived_from`, claim type, and explicit confirmation rules. Add both cases as poisoning probes.

10. **Major — Public/private separation needs a rule for derived media and persona history.** Mode 1 may read the persona’s public history, while Mode 2 must never read private data; private facts can nevertheless enter persona utterances, visual-state frames, summaries, or reference images. A private “last displayed frame” used to start a public world session is a direct leak path. Tag every derived artifact with source scopes, prohibit private-derived artifacts in Mode 2, and test fresh public-session startup after a private session.

11. **Major — Correction and deletion conflict with the proposed append-only episode log unless storage semantics are defined.** §5.6 says to delete episodic mentions while retaining an audit history and a deletion ledger. Specify tombstoning versus physical erasure, indexes and embeddings, backups, already rendered media, and in-flight prompts. A correction also needs to invalidate derived summaries and visual references, not just set `valid_to`. Verify deletion by querying every store and output channel after cache flush and session restart.

12. **Major — The TVC budget mixes unpaced and paced timing.** At 16 fps, `P = 12/16 = 0.75 s`; with `T = 0.549 s`, an unpaced client gains about **0.201 s of backlog per chunk**, so a one-chunk `Q` bound is impossible without effective gating. Once generation is gated to playback, the wait to the next generation opportunity is no longer generally `U(0,T)`; it can approach a playback period. The listed p50 and p95 are illustrative sums, and saying p95 sums overstate the true p95 does not validate a 3.2 s p95. Simulate and then measure the joint timestamp distribution, including stalls. The 2-GPU, 12-fps regime needs the same pacing analysis.

13. **Major — Speech and shot timing remain on the critical path.** The 0.75 s speech sum omits the avatar delay that §5.5 says is added before audio playback; with a 300 ms avatar latency, first audible speech is about 1.05 s unless rendering overlaps or is pre-rolled. World-shot event acknowledgement does not guarantee that its chunk is presented when narration plays. Define a shared presentation timeline for TTS packets, avatar frames, world chunks, and cuts, then measure first-audio latency and A/V offset from that timeline.

14. **Major — The feasible demo and resource gate need a sharper boundary.** The 4+1+1–2 GPU arithmetic is correct at 6–7 GPUs, but concurrent world generation during presenter shots, a VLM monitor, and shared-GPU contention make it an optimistic reservation estimate. C2 reset/extend and C5 seamless visual restart are also larger than their labels imply: session length and state are fixed at start, and a stored displayed frame does not preserve KV or decoder state. Define the first demo as a measured configuration with fallback to presenter plus pre-rendered clips; label live world events, long sessions, and seamless restarts as gated extensions.

15. **Minor, relevant to CP4 — Some success statistics need a defined denominator.** Declining unsupported controls can improve compliance measured only on attempted items while reducing coverage. Report instruction-level success, refusal/degradation rate, and compliance conditional on execution. If more than 5% of TVC observations are censored, an unconditional p95 may be unidentifiable; report deadline success and restricted time measures instead.
