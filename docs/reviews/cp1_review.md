1. **Blocking — The proposed demo may exceed the backbone’s controls.** The [upstream recipe](https://github.com/vllm-project/vllm-omni/blob/main/recipes/Robbyant/LingBot-World-2.0.md) describes an image-conditioned world generator with public mid-session **camera** control. It does not establish character gestures, expressions, speech, or public mid-session prompt switching. The recipe page I could access was `main`, so this does **not** verify the author’s claim about commit `7b4dc7633bde`. **Fix:** make a control-to-observable-behavior table from the pinned code and choose a persona demo only after each required behavior has a verified implementation path or an explicitly scoped additional component.

2. **Major — The acceptance scenario and “real-time” requirement remain undefined.** [PROJECT.md](/data/zhoutaichang/live-agent/docs/PROJECT.md) assumes both private interaction and livestreaming while postponing the focused scenario. That leaves response timing, interruption behavior, and memory boundaries untestable. **Fix:** specify one initial user journey, supported actions, session duration, and proposed targets for speech response, correctly conditioned visual response, and p50/p95 end-to-end latency. Treat the second mode as a later evaluation scenario.

3. **Major — Feasibility assumptions are recorded too confidently.** A1 reports GPU inventory as “observed,” but inventory does not establish schedulable access, memory available to one job, throughput, or support for this model; the recipe reports validation on H200/B200. The local MiniMax H3 copy also has unverified provenance, license, and usable interfaces. **Fix:** separate observed inventory from available capacity, add these as open questions, and identify the smallest permitted benchmark and provenance checks that would settle them.

4. **Major — The hypothesis is testable in wording but lacks a competing account.** The spec says video generation alone may be insufficient, yet does not require comparison with simpler approaches that might meet the focused demo without the preferred architecture. **Fix:** carry forward explicit alternatives, including a simple agent plus avatar or video baseline, and state what result would favor each approach.

5. **Major — The “single source of truth” omits several binding requirements from [goal.md](/data/zhoutaichang/live-agent/goal.md).** The spec does not explicitly carry forward the six required research areas, the related-work matrix fields, architecture comparison, full proposal sections, evaluation controls and uncertainty reporting, or the instruction-file deliverables. A pointer to the brief helps, but calling the shorter document authoritative can weaken those requirements. **Fix:** add a compact requirement-to-deliverable checklist and state that the original brief governs requirements while `PROJECT.md` tracks their current interpretation.

6. **Major — The review log procedure needs a reproducible evidence trail.** Recording date, model, revision, issues, and resolutions is a good start. It does not require the exact submitted prompt and evidence bundle, reviewer output and rollout identifier, source-code commit, working-tree state, or a link from each disposition to the revision or evidence that resolved it. **Fix:** require those fields per checkpoint and mark unresolved findings explicitly; re-review material revisions against the new artifact.

7. **Minor — The thin instruction-file structure is sound, with two consistency fixes.** [CLAUDE.md](/data/zhoutaichang/live-agent/CLAUDE.md) says “video + speech” where the brief qualifies speech as “where supported.” [AGENT.md](/data/zhoutaichang/live-agent/AGENT.md) says `PROJECT.md` wins any disagreement, potentially overriding the owner’s brief. **Fix:** preserve the speech qualifier and make disagreements with `goal.md` visible for resolution rather than silently assigning precedence.
